# Common document patterns

Minto observes that most business documents answer a handful of recurring questions. For each type, here is the SCQ skeleton, what it usually looks like with content and the key line that normally follows it. They are starting points: if the material calls for another structure, the material wins.

In almost all of them, the question stays implicit in the text, but write it down for yourself before drafting.

## 1. Asking someone to do something (giving an instruction)

Here the introduction doesn't remind the reader of a question: it plants one.

```
S = We want to achieve X
C = To do that, we need you to do Y
Q = (How do I do Y?)
A = Steps, each with a date and a result
```

When the question is "how?", the answer is almost always steps in chronological order. The complication and the answer are usually the inverse of each other: the answer is the effect of carrying out the steps.

Variant for procedures: S = you do X; C = it has to be done in a specific way; Q = (what is that way?).

## 2. Requesting approval for an expense or investment

The reader's question is always "should I approve it?".

```
S = We have a problem (described with data)
C = There is a solution that costs N
Q = (Should I approve it?)
A = I'm asking you to approve it
```

Usual key line, in this order:
1. The problem can't wait.
2. This action solves it (or is the best way to solve it, if there were alternatives).
3. The cost is offset by the expected savings or return.
4. Additional benefits, only if the data supports them. If not, leave it out.

Point 1 lets you lay out the problem in detail; point 2, the solution; point 3, the financial analysis.

Cost alone is not a reason to approve: it goes in the main idea ("I'm asking you to approve X, which costs N") or inside point 3. If there's no data to show it pays off, point 3 stays as `[missing: ...]` and is not asserted.

## 3. Explaining how to do something

```
S = We want or need to do X
C = We don't know how, or we're doing it wrong
Q = (How do we do it?)
A = Steps or changes, written as results
```

It works both for something the reader has never done and for something they already do and need to do better.

## 4. Choosing between alternatives

Minto warns that, if the problem is well defined, strictly speaking there are no "alternative solutions": something either solves it or it doesn't. A document about alternatives makes sense when the reader already knows the options because they were discussed before.

```
S = We want to achieve X
C = There are several ways to do it: A, B and C
Q = Which one is best?
A = B is best
```

Preferred key line: organized by the **criteria** used to decide (cost, timing, risk...), showing how B wins on each one. If that's not possible, by the reasons each discarded alternative falls short.

## 5. Proposal to a new client

```
S = You have a problem (one or two sentences)
C = You decided to seek outside help to solve it
Q = (Are you the right people?)
A = Yes
```

Usual key line:
1. We understand the problem.
2. We have a solid approach to solving it.
3. We have experience applying that approach.
4. The commercial terms make sense.

Use it when it pays to spend space explaining the problem, because doing so demonstrates knowledge. In the text, the complication and the question usually stay implicit: "It was a pleasure discussing [problem] with you. This document sets out how we propose to help you [desired result]".

## 6. Proposal to a known client, or when the proposal is a formality

```
S = You have a problem (explained in three or four paragraphs)
C = You want help solving it
Q = How would you help us?
A = The approach
```

The body is organized around the approach, because that's what the client decides on. Experience is woven into the explanation of the approach, not in a separate section. The commercial terms can go in a separate letter or section.

## 7. Progress report

The first one:
```
S = We are working on problem X
C = We said the first step was to find out whether Y. We've done it
Q = (What did you find?)
A = The finding
```

The following ones:
```
S = At the last review we told you X
C = You asked us to look into Y, and we've done it
Q = (What did you find?)
A = The finding
```

The answer opens with what was found, not with what was done to find it.

## Mapping to the reader's question

| Question | Pattern |
|---|---|
| What should I do? / How do I do it? | 1 or 3 |
| Should I approve it? | 2 |
| Which one do we choose? | 4 |
| Are you the right people? / How would you help us? | 5 or 6 |
| What did you find? | 7 |
